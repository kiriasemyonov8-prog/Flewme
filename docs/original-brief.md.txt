* PWA для установки на домашний экран смартфона;
* возможность дальнейшего развития в сторону Android и iOS;
* облачное хранение данных, когда оно действительно понадобится;
* подключение ИИ через API на отдельном уровне приложения.

Supabase можно рассмотреть для аутентификации и хранения данных на подходящем этапе, но его внедрение ещё не утверждено.

Для первого прототипа нужно выбирать минимально достаточную архитектуру. Не добавляй инфраструктуру только потому, что она может пригодиться когда-нибудь.

Проект должен быть экономичным и понятным для дальнейшей самостоятельной разработки.

Я планирую использовать Claude Code. У меня есть Windows-ноутбук и iPad, поэтому в дальнейшем желательно организовать работу так, чтобы я мог продолжать проект с обоих устройств.

Приоритет — сначала качественный мобильный прототип, затем развитие функциональности и платформ.

11. Требования к первому прототипу

Когда я разрешу начать разработку, прототип должен позволять оценить прежде всего:

* внешний вид продукта;
* различие двух режимов;
* удобство основных экранов;
* иерархию финансовой информации;
* работу карточек и быстрых действий;
* переходы между разделами;
* удобство интерфейса на смартфоне;
* узнаваемость визуального образа Флюми.

Допустимо начать с демонстрационных данных и имитации некоторых сценариев, если они явно обозначены и не выдаются за настоящие финансовые операции.

Не нужно на первом этапе строить полноценную банковскую инфраструктуру, подключать реальные счета или внедрять сложную финансовую аналитику.

При этом интерактивные элементы прототипа должны вести себя последовательно. Не создавай кнопки, которые выглядят рабочими, но ничего не делают.

12. Принципы совместной работы

Работай итеративно.

* Не принимай важные продуктовые решения за меня, если они меняют концепцию.
* Не меняй утверждённые элементы дизайна без согласования.
* Не добавляй функции ради количества.
* Не перегружай интерфейс.
* Если замечаешь проблему, объясни её и предложи конкретное решение.
* Отделяй уже утверждённые решения от гипотез и открытых вопросов.
* Если есть несколько вариантов, сравнивай их по пользовательской ценности, сложности и стоимости.
* Сначала объясняй суть простыми словами, а технические подробности раскрывай по необходимости.
* Не переходи к следующему этапу, если я явно прошу продолжить обсуждение текущего.

13. Текущий этап работы — не начинать разработку

Сейчас мы находимся на этапе уточнения концепции.

Не создавай приложение и не изменяй файлы проекта без моего явного разрешения.

Твоя ближайшая задача — изучить этот документ как продуктовое техническое задание, выявить противоречия, неясные требования и важные решения, которые ещё предстоит принять.

Не нужно сразу выдавать огромный список вопросов или заново обсуждать то, что уже зафиксировано.

Помоги мне последовательно подготовить концепцию к реализации. Сохраняй утверждённые решения и обновляй рабочую спецификацию по мере наших договорённостей.

Начинай с анализа текущего ТЗ. Не пиши код, не создавай проект и не запускай команды.
